# AM6B 115资源目录 1.1.0

来源：[115资源](https://docs.qq.com/sheet/DTU5jRklaWUJtTEZX?tab=000001)，2026-09-26 公开页面快照；另含用户于2026-10-15提供并逐条核验的55个补充分享。

此模块为现有影院提供115分享，选源界面与其它实际115来源统一显示“115 网盘”；内部保留原provider和出处，与漫迪、BT及已有115统一混排，沿用画质与影片身份过滤。按当前用户偏好，手动点选影片后等待用户选择具体片源，不再自动倒计时选源。分享查询本身不转存、不创建云任务；分享中有文件不代表个人115已准备完成。不改变皮肤或内核。

## 工作方式

- 汇总左右栏独立归属，147 个目录组、214 个分享链接，89 个映射页签。页签无文本、过期分享和缺少明确影片身份的条目不是可播放保证。
- 用户补充55个分享中，39个在核验时有效（10个原有、29个新增），15个明确不可用，1个错误码无法确认为有效。旧目录C15被明确失效状态禁用，但其旧身份仍保留。原目录其余链接不因此被宣称已重新核验。
- 补充快照读取291个目录页，保留14977条真实目录/文件名称用于路由或溯源；这是作品目录层索引，不是全盘所有文件的递归盘点。音乐、ISO、压缩包及不满足电影/剧集身份的文件不会伪装成可直播片源。
- 本地 SQLite 索引先选择最多6个相关合集。一个后台任务最多8次查询，最多18秒，并服从现有30秒总搜索预算和取消信号。API 每次4秒超时，无自动重试。
- 明确不支持的文件后缀不占路由预算。同分合集按作品身份和组ID稳定打散，不按“旧目录/补充目录”的字典序排序；实际影片分辨率和身份规则不变。
- 查询成功缓存6小时，空结果10分钟，失效分享15分钟。最多显示16个去重文件。既有画质过滤和排序继续生效。
- 实际文件必须匹配可信影片别名和明确年份，剧集还必须具有正确的单集 SxxExx。年份缺失、模糊编号、整季包、ISO原盘、压缩包不自动作为直播文件。
- 同一电影的首映年与主发行年可能不同；仅接受同TMDb ID官方详情证明的首映/院线年份，不使用任意相邻年份或分享自称的年份清单。
- 表格单元格是目录路由线索。分享当前内容可能比快照新，播放地址来自分享实际文件，不把表格文本当视频URL。
- 字幕是否存在及同步需要播放验证，文件名中的“中字”“双语”不作为已验证证据。

## 登录、选择和地址

使用独立的115 Linux客户端扫码登录，不使用或修改CD2账号。凭据仅在盒子 `/storage/.local/share/am6b-qqdocs-private/115-os_linux.json`，不得导出或粘贴。

选择卡片只保存稳定的 `am6bqqdocs://单元格/文件ID`；新增分享使用固定 `supp-<分享码哈希>` 命名空间，原单元格不重排、不改变指向。点击时读取Linux分享下载接口，复核文件ID、文件名和大小。临时地址只交给播放器，不进入本模块或影院30天快速播放缓存。只传User-Agent给文件CDN，不传账号Cookie。

`last-resolution.json` 只保存文件身份和地址哈希，便于核对原生播放器回执，不包含地址、Cookie或Token。模块缓存位于自己的 `userdata/addon_data/script.module.bobbi.catalog/`。

## 维护和关闭

Kodi → 我的插件 → 模块/依赖 → AM6B 115资源目录 → 设置，可关闭原有“在影院选源中显示腾讯目录来源”开关。该开关同时控制本模块的腾讯快照及补充分享，不影响个人CD2库和其余提供方。

目录为可重复生成的版本化快照，不会静默抓取或升级。维护脚本在本轮 `repair286`：`summary_catalog.py` → `pull_catalogue.py` → `build_catalogue.py`。输入公开数据不执行JavaScript、宏或表内指令。每次更新先跑身份、来源隔离和部署回退测试，再精确校验文件哈希。

补充构建入口在当前发行的 `catalog-maintenance/build_supplement.py`，输入为该目录的 `manifest.json` 和证据快照，基库为本发行 `baseline/addons/script.module.bobbi.catalog/resources/catalog.sqlite3`。输出必须为新路径，经核验后才加入新发行；不原地修改冻结基库。详细规则与离线测试见 `catalog-maintenance/README-builder.md`。

分享授权失败时不重用CD2会话，应通过官方二维码更新独立Linux登录。账号查询错误不会阻断其他来源。

## 回退

以当前发行目录的 `MAINTENANCE.md` 和精确事务清单为准，不沿用初始接入版本的“五文件”回退假设。使用维护端 `deploy.py rollback --transaction <deployment结果中的精确事务路径>`，只在空闲且当前哈希仍匹配时执行；不删除账号数据或动无关插件。
