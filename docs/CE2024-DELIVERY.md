## 3. 实际安装发现的死锁及修复

CE2023 在 `default.py → bootstrap → Installer → KodiHost` 两次停于 switching。现场栈显示 GUI 线程等待 ScriptInvocationManager，安装线程等待同步 `executebuiltin(..., True)` 的 SendMsg。核对 Kodi 21.3 实现：同步调用不释放 Python 锁，而服务 Stop 在持有 invocation manager 锁时需要取得 Python 锁，与现场死锁链一致。

CE2024 将 UpdateLocalAddons 改为异步提交，同一 GUI 队列追加唯一完成标记；通过 `Monitor.waitForAbort` 有界等待，释放 Python 锁。没有收到标记不能算刷新成功。InstallAddon 同样异步，以真实版本回读完成，不放松原事务或增加总超时。

新增正常、失联、取消和迟到标记测试。原依赖夹具缺 `xbmcgui` 的首次失败保留；补齐真实异步模型后 77 项通过。

设备事实：

- 两次失败安装通过原产品 recover 恢复，未手改 journal。
- CE2024 入口成功安装，`installation.json` phase=`complete`，sequence/high_watermark=`2026102024`。
- 1143 个波比自有运行文件与实际包逐一匹配，无差异。原插件依赖及用户数据不强制覆盖。
- 入口文件夹由可恢复维护工具暂存，再操作真实菜单；**未认证 Kodi ZIP 浏览器导入的完整流程**。
- 后续一次热态 UI 测试超时，空闲重启后复测通过。热态超时根因未完全确定，不能声称已经修复。
- 旧维护 updater 的另一份 state.json 仍为 CE2021；它不是本次实际入口的安装记录，未强行改写它来制造一致。
