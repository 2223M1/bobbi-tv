# AM6B+ 观影回归

在有授权的测试盒上运行。保留播放器、账号和已连接的来源，先记下版本、当前窗口、正在播放的内容及 Kodi 日志起点。已有用户播放时等它结束。用现有首页和目录进入真实内容；每次失败在同一个选源面板内换源。给每步记录时间、窗口、焦点、选中行、可见画面和结果。

**先关 HDMI-CEC，再动实机。** AM6B+ 的 Kodi 外设设置和 Amlogic 驱动是两个开关。将 [CEC 测试脚本](../../tools/am6b_cec_test_guard.py) 复制到盒子，在家庭 Kodi 空闲且 CEC 外设与开机、待机、切源动作已关闭时执行 `python3 am6b_cec_test_guard.py disable`。须读回 `mask=0x0`、`profile_off=true`、`cec_device_open_processes=0`。脚本只更改驱动本次运行的掩码，保留关前值，不改家庭配置；任一条件不符便停止实机操作。

新建的官方 Fuse／Nara 测试配置可能恢复 Kodi 出厂 CEC 默认值。在首次启动前对每个已标记的隔离配置执行 `stage --profile <隔离目录>`，启动测试 Kodi 的临时 systemd 服务屏蔽 `/dev/aocec`。切皮肤、重启 Kodi 前后和恢复家庭首页后，分别对对应配置执行 `verify`。全程用 Kodi 网络遥控；不要发送电视开机、待机或激活信号源的 CEC 命令。完整重启盒子另须通过 `verify --before-box-reboot`：启动配置可在 Kodi 之前重新打开驱动，检查未通过就不重启盒子。结束时保持 CEC 关闭，不自动重开。

| 路径 | 操作和通过条件 |
| --- | --- |
| 实时玻璃 | 在已开启实时玻璃的盒子上，通过现有安装器装完整签名候选并重启 Kodi。保留开关，勿逐个覆盖插件版本或手写回执。进入带背景图的目录，再打开原生选择弹窗；两个画面各运行盒端只读探针（将仓库的 tools/ce_check_live_glass.py 传到临时目录，用 python3 -IB 运行）。要求当前完整安装通过校验、Kodi 实际映射渲染库、屏幕有玻璃区域且有新交换帧。对照同窗口同焦点的静态／实时 framebuffer。已选择经典的设备按经典验收，不代改偏好。 |
| 普通影视推荐 | 给同片、同集的电影与剧集依次提供普通 WEB 和较晚返回的 4K 蓝光 REMUX，观察推荐标与可见顺序，移动焦点后补查一次。已有选中项、筛选和手选文件身份须保持；无码率实测时不要把命名当作播放质量证明。同时用带压制组和中字的动漫回归原顺序。 |
| 遥控连接 | 进静态界面，唤醒屏保。在同一画面比较空名字、Phone、Yatse 三次真实 EventServer HELO 前后的通知区域；避开时钟。普通 Kodi 通知作阳性对照，必须能看到。 |
| 目录 | 从首页分别进电影、剧集、动漫；移动海报，切换分类，试无结果的搜索，再返回有条目的页。用方向键恢复海报焦点；空页要有能继续操作的可见控件。检查本段日志无 control 50/1000 聚焦失败。 |
| 设置入口 | 依次从设置两栏用方向键进入液态玻璃、顶栏导航和控制栏自动隐藏，核对落在该控件且未切换开关。四个标有“打开插件总设置”的入口只打开插件本身，左侧所示类别须能在实际插件页找到；每次返回仍在原分类、原行且高亮。中英文各走一次。 |
| 选源行布局 | 在影院皮肤原生入口和独立 direct 窗口观察同一组短/长名称、115/BT、大小、字幕与做种；在筛选按钮和片源行间往返，检查普通行、聚焦行、空列表和返回。在构建前运行 `python tools/generate_source_rows.py --check`。 |
| 换源 | 第一批结果出现就点进一个真实失效的片源。验证列表仍可见、原选中行和焦点恢复、instant_close=false、失败原因可读。让尚在查询的来源按原时限返回，实测同一列表能补齐，再从中换可用来源。选源后不发确认键，检查旧错误框自行退场，原生播放进入全屏。 |
| 选源卡 | 在同一部影片的 115 和 BT 行上各留一帧，检查类型、清晰度、大小和实际可得的中字／做种信息。字段绑定本身不能证明用户看得见。 |
| 源库与筛选记忆 | 在有两个源库的同一影片检查卡首库名与独立网盘名。通过“筛选 → 源库或来源站点”选一家，再打开另一影片或剧集；无命中保持空列表，迟到批次、重试、自动选源都不得越过条件。重启 Kodi 再查看，主动重置后才恢复全部。按 Kodi 资料隔离；不要注销或覆盖用于多账号测试的连接。库名缺失时记录可区分编号，不用文件名或分享码猜库名。 |
| 电影与番剧 | 给出目录 ID、分季、集数和选定的发布组。测试已映射和未映射的完结番各一部；没有文件级证据时不猜集。分别记录元数据、选中的文件、原生 AV_STARTED、全屏窗口和两个间隔至少 8 秒且前进的播放时间。 |
| BT 和第三方对照 | 对“其他皮肤能开、波比打不开”的样本，按[同文件实机流程](../bt-playback-parity.md)走一次家庭源卡冷起播，再在同一台盒子的波比和参考皮肤视频目录里遥控点同一文件。记录文件指纹、实际播放时钟和缓存条件；参考能开而波比不能、证据不全或实播卡顿，都不能标为全部通过。聚库走网盘离线时另列路径。 |
| 文件选择 | 只按一次片源：过滤后零项返回选源并保留原因，一项直接打开，多项才显示文件列表。用同一部完结番分别核对片源内总视频数、目标集与实际文件。单项但未独立验证身份，只允许本次播放，不能授权续播或云准备。再测试两个版本选第二项、取消不播放，以及选定后文件变更时拒绝打开。 |
| 字幕 | 播放无内封中字的外语源，记下原轨道、自动外挂轨和启用状态。在无私人 OpenSubtitles key 时进已有“找中文字幕”，选择结果并在原生文件浏览器中确认。验证轨道及手动意图发生变化，播放持续。 |
| OSD | 用同一遥控依次暂停、恢复、快进和快退。核对声音／播放速度／时间进度，无重复执行和成功提示。延迟以发包到 Kodi 可观察状态的变化计，不能当成手机触屏或 HDMI 显示延迟。 |
| 服务与收尾 | 分别查 Kodi、TorrServer、Jackett、TMDb 路由和备用代理。CD2 的端口、实际 115 挂载、索引文件能读取都要检查；只看容器 running 不够。统计本轮日志内的焦点错误、锁冲突和重复连接告警。停止自己启动的播放，回到首页。 |

`tools/ce_incident_remote.py` 提供真实 HELO/BUTTON/BYE。例：`python tools/ce_incident_remote.py BOX_IP --name Phone measure right`。GUI 状态由 Kodi JSON-RPC 读取；实机帧取自 framebuffer，硬件直出的视频平面可能不在截图中。第三方时间到期、撤销分享和种源不可用各自记录，不使用假回复补全。截图和日志放测试机的私有目录，不把播放 URL、Cookie、账号或原始日志放入仓库。

备用 TMDb 代理若目标离线且主路直连正常，可在支持 RestartSteps 的 systemd 255+ 使用同目录的 `am6b-tmdb-proxy-backoff.conf` 作该服务 drop-in。仅调整重试：30 秒起、4 级、最高 10 分钟，当目标恢复时仍会再试。移除本次专用 drop-in、重载并重启该服务即可恢复原策略。

## 首页、整理、续播与库查询回归

| 现有流程 | 验收方式 |
| --- | --- |
| 首页行与空间 | 打开已有的管理入口、移动一项后取消，读回原设置。保存中切换 profile 的用例应停止余下写入；用具名测试配置验证，不改家庭成员设置。 |
| 双端整理 | 对片库一致性副本里的一个模糊文件，先打开电视预览，再在手机版网页确认同一条目。旧电视预览不能覆盖新修订。重新读回并撤销，双方仍指向同一原文件；对比家庭片库原记录。 |
| 选源与输出 | 区分分享撤销、文件不匹配、预载不足和播放器未确认起播。失败返回原列表。只读显示页记录盒端 HDMI 模式，电视/功放接收端无独立读数时填未知。 |
| 卡片动作 | 让目录和首页各展示同一账号的单版、多版、文件夹；不同账号复用同一作品编号。检查可用动作而非只比文字。多版重新选择播放起点；切换账号、其他服务器迟到和取消都不能启动旧卡片。 |
| 音轨与字幕 | 用两个具有相同轨号但不同语言次序的本地短片，实际操作 OSD。换文件前保存的选择不能改新文件；检查强制字幕、手动关闭、旧操作迟到，以及重新打开面板后的有效选择。普通 Kodi 的重新读取不是原子控制回执。 |
| 大库 | 在隔离目录执行 tools/benchmark_catalog_pages.py：--create 只创建新的合成索引；同一数据库做前后对照。记录首个连接、暖查询分布、SQL 次数、返回体及下一页摘要。冷连接不代表清空系统磁盘缓存；真实库另以只读连接测量。 |
