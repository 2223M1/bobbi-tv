基线为 main `1d421b101bdc3b940bdd5870caaac49a5fc49394`，未撤销通用化合并。
本轮只改 CE，独立完成，未使用子代理。输入原审查与原始反例完整保存在
[ce2009-prealpha](../review-evidence/ce2009-prealpha/BobiTV-CE2009-PreAlpha-1d421b1-Review-20261020/README.zh-CN.md)。

## 改动及边界

| 项目 | 实际实现 |
| --- | --- |
| A01 | 文件可运行与宿主操作完成分离。持久化待激活/待恢复，重开幂等补齐启用向量和皮肤；读回确认后终结。 |
| A02 | 成功读取明确无关视频后撤销旧会话后继；清候选并取消 worker，不停止外部视频、不清列表。空路径、开播/seek 读取错误不等于接管。 |
| A03 | 后继提交边界隔离异常，区分 `before_submission_failed` 和 `submission_unknown`；结果不明不重发，驻留宿主继续处理下一次用户操作。 |
| A04 | 片尾前单 worker、5/15/30 秒退避，最多五次发现；自然结束后最多一次补查，20 秒绝对有效期不因候选/外部播放延长。 |

仍复用现有准确同版策略，重查不提交云任务、不扩大匹配范围、不降音画质。
原生 F9 owner、字幕/字体链、手动字幕 Off、账号代际与 block 默认不变。
无新增型号白名单、未知设备警告、第二台硬件认证门槛或新后台服务。

### 安装 journal 的兼容语义

- `staged/switching/restoring`：文件未确认一致，禁止影院启动。
- `activation_pending`：新程序已整体核验，可启动；启用操作仍须重入与读回。
- `restored + host_pending=restore`：旧程序文件已恢复，可启动；启用/皮肤尚未确认。
  `restored` 在这里是兼容旧 CE2009 boot gate 的**文件状态**，不是事务完成回执。
  新入口 bootstrap 始终先调用 recover，忽略 pending 才会复现旧缺陷。
- `complete` / `restored` 且没有 `host_pending`：宿主读回成功，事务完成。

恢复过程不再次搬动已恢复文件。中间 CE2010 的 `restore_pending` journal 会先转成
兼容状态再启用旧服务。高水位在已核验新代次可运行前持久化，回退不放开旧包重放。
账号、观看/媒体库及无关插件不回滚。入口自身由 Kodi 更新，不在影院程序回退向量中。

## 恢复与合并

普通安装：先装新入口 → 打开“波比开始使用”恢复未完成操作；需要回退时选择“回退上一次程序安装”。
如果上游依赖缺失按 Kodi 原生提示处理，不重置账号与 userdata。

已知 AM6B 维护部署只用对应冻结 run 回退一次：

```powershell
python tools/deploy_ce_candidate.py --transport-source 'D:/AM6B-Project/AM6B/.claude/worktrees/bobi-tv-redesign' --mode status --run-id 20261020-203300
python tools/deploy_ce_candidate.py --transport-source 'D:/AM6B-Project/AM6B/.claude/worktrees/bobi-tv-redesign' --mode rollback --run-id 20261020-203300
```

该 run 回到本轮中间 CE2010；若需继续回到2009，先检查203000的冻结记录和当前代次，再使用
该run，不能跨代直接调用旧回滚。不要以整库备份覆盖账号/观看数据。

GitHub 保持私有，新分支提交后需候选 head 与实际 PR 集成树 CI 全绿才正常合并；不强推、不
覆盖旧包、不公开发布。最终精确 commit/tree、CI链接与交付状态另见私库 PR 和草稿交接文件。
