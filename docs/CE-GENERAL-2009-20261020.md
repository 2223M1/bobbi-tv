# 通用 CE / 2026102009 交付与审查入口

本轮独立完成、未使用子代理。按新的通用 CE 计划纠正此前 F9-only 产品范围。
输入原件：[Web 计划](../review-evidence/ce-general-plan/web-input.zip)。Android/Windows 未继续。

## 实际改动

- 一个 Kodi 安装 ZIP 内带完整签名代次和同源安装器 bootstrap。无需 SSH、旧 Jacktook、
  手工拼装九包或导入维护者账号。首次登录、影片资料、选源共用现有业务核心。
- 按可用 RPC 和原生协议响应选适配器；型号、SoC、测试标签与未知 Kodi 哈希不参与准入。
  GUI 与驻留服务共用适配器结果，避免启动探测短暂失败后两边选了不同协议。
- 普通 Kodi 的驻留 `StandardPlayback/StandardSession` 观察实际 AV，绑定请求和播放文件。
  没有伪造 native receipt；错误/早停不记看完，换号/选择 B/取消后丢弃 A 的迟到结果。
- 复用实际文件解析、同版规则和字幕发现。已知旁挂随 ListItem 开播绑定；普通 API 无
  原子手动意图守卫时，迟到候选交给字幕菜单，不自动覆盖用户关字幕/换轨。
- 同版下一集在接近片尾时后台准备；只有最近片尾观察配合 Ended 才自动交付一次。
  手动选了歧义文件不获得自动续集资格。历史写盘移出播放器观察线程并隔离磁盘异常。
- 原生 F9 owner、字幕/字体与准备链保持；不重载皮肤、清列表、全局循环 Stop 或降低音画质。
- 安装事务只换自有程序，先暂存再核验整套，失败恢复，账号与观看数据不回滚。
  缺失的原版依赖补装签名载荷原件；已有版本/origin 不被覆盖，过旧版本交 Kodi 更新。
  保留反回放高水位、完整签名、组件哈希、归档路径/尺寸和 ABI 检查。
- 2008 中间候选实测后修正了“更新入口总是选择内附旧包”的交互；2009 可选择新包。

已按精确备份升级至 CE2009，run `20261020-184100`。无账号迁移，不动 F9、SYSTEM/eMMC、
CD2 1.0.19、挂载、Yatse、VPS newapi 或代理。中间 2008 首次预检退出发生在服务/程序修改前，
安全检查后同载荷重试成功；保留[首次失败记录](../review-evidence/ce2008-first-upgrade-attempt.json)。

新电影《这个男人来自地球》此前未测：115 BeiTai 1080p HEVC、英语 DTS-HD MA 5.1，
实际启用简体 PGS，窗口 12005 全屏。首次启动监测 **不通过**：旧判据异常累计 7.515 秒，
其中有媒体时钟滞留但解码进展，也有 2.483 秒 caching 与解码计数停滞。不能把全部 7.5 秒
解释成画面静止，也不能把它抹成无问题。随后独立 30 秒观察通过、无解码错误。
保留[首次启动](../review-evidence/ce-new-work-man_from_earth-select-1792492324782525900.json)
和[后段观察](../review-evidence/ce-new-work-man_from_earth-observe-1792492402664895600.json)。
电影在2008测试，2009仅安装入口/平台安装器改变，播放器与字幕字节未变；不重复计新作品。

新动漫《玲音》S01E01，115 Ghosty6464 JP-BD 1080p H.264、日语 FLAC 2.0，已进入全屏播放，
后段[30秒观察通过](../review-evidence/ce-new-work-lain-observe-1792493227300176500.json)，
无解码/丢帧错误；[首次启动仍不通过](../review-evidence/ce-new-work-lain-select-1792493159293205200.json)，
异常累计7.964秒。所选版本只有英文内嵌字幕，自动流程明确显示“未找到匹配中文字幕”，
未伪装匹配成功，也没有换成低质量版本；因此该片**中文字幕验收未通过**。

普通 CE 的定制原生原子能力不能假造。字幕候选开播后到达需手动应用；标准路径中的高级
prepared-font 激活不宣称与 F9 原子守卫等价，Kodi 内嵌字体/既有字体设置不被禁用或覆盖。
新用户真实扫码、第二账号、其它 CE 硬件、电视端 ASS/PGS 外观/HDR/直通仍需内测确认。
当前允许小范围私下内测，不以没有第二台设备为安装或合并门槛；稳定公开发行仍关闭。

普通适配器还在现有盒子的真实 Kodi/Python 中跑了两个独立生成的 8 秒短片：
`StandardPlayback → ListItem → getPlayingItem → Ended → 下一片`，两个实际 AV 和两个自然EOF
[均通过](../review-evidence/ce-standard-device-fixture-1792493020915359500.json)，没有调用私有
原生 API，没有复制账号，也没有把合成短片计入新电影/动漫覆盖。其下一片是固定测试输入，
同版选择本身由上面的真实产品策略测试覆盖，不能冒充剧集完整播到下一集的实测。
首次两次 fixture 失败是测试脚本把注册调用放在 assert 内，被 Kodi 优化模式移除；
产品入口没有这个写法。修正 fixture 后通过，原失败回执留存，不删除或改写为通过。
