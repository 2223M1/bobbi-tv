# 三端候选实测发现与处理

这些不是只读推测：1903 部署后实际选源与播放暴露了如下通用问题。
修复不改变原码流，不放宽作品/版本身份，不引入新的常驻 Juku 后台。

| 发现 | 根因及修复 | 证据边界 |
| --- | --- | --- |
| BT HTTP 成功但最后零候选 | portable 请求被串行执行；慢请求耗尽共同截止后，连已成功响应也没有解析。改为最多四个跨解释器 IO 槽，成功响应到达即解析/发布 | 测试覆盖乱序、取消、超限、坏 XML、阻塞槽；真实最终搜索另记 |
| TMDb 资料成功后抛异常 | stateless transport 已自行关闭，旧 finally 仍引用不存在的 `_session` | 移除错误清理；两类元数据回归通过 |
| 其他已准备版本字幕找不到 | 仍查旧平铺 resources.sqlite，未按当前账号代际寻找 | 只读取当前 scope；退出/换号/迟到结果不复用旧库，缺库不阻断其他字幕来源 |
| Windows 有音画但无法进入前台 | resolver 的 onInit 把系统 busy ID 当作自己的窗口，等待错误窗口后过早交接 | 根据窗口私有 token 核实实际 ID，等待所属窗口退场；不放宽 native modal/generation 校验 |
| CE BT 子解析器立即退出、父级仍等待 | 首次移植遗漏 JackTorr 子级；旧组件仍读取旧会话名、调用旧 IPC | 新增独立薄 BT 解析组件，沿用已有 TorrServer；新旧配置只迁移连接字段，不启动第二后台 |
| CE 某次片尾后没有续播 | 严格同版证明未通过，且未抓到原生终态 reason，不能断言正常 EOF | 不改准入；新增经过 receipt 校验/去重的终态固定字段诊断，先于 cancel。下次真实验收另记 |
| 射手候选下载失败 | 官方 detail 成功，官方下载重定向链返回 HTTP 493 | 不绕过限制，不把候选当已加载；影片播放不受字幕下载错误阻断 |

Windows resolver 根因和已执行的失败/成功尝试见
`review-evidence/windows-fullscreen-retirement-20261019.md`。
CE 新作品的身份、失败尝试、真实字幕与未验收范围见
[NEW-WORK-ACCEPTANCE-20261019.md](NEW-WORK-ACCEPTANCE-20261019.md)。

1905 Windows 另有一次 42 毫秒内交接早拒绝，尚不能证明与初次窗口识别根因完全相同。
后续安全修正仅在 Kodi 官方 Python 窗口范围 13000–13099 读取可见性及私有 token，
要求唯一匹配；不创建空槽 `Window(id)` 对象（实验版曾因此挂起，失败记录保留）。
安全修正的同片源回归通过全屏和连续观测；不以一次成功抹去未解释的原始失败。

## 不被这些修复替代的验收

- 首次扫码、真实 A→B 换号仍需真实账户条件，单账号及模拟回归不代替它。
- Android 未证明可可靠远程返回 CE，未切系统、未安装，不把 APK 构建称为真机通过。
- 本机个人 TMDb 配置只用于隔离试播，未进入安装包；专用应用配置仍未完成。
- HDR/DV、音频直通、长时间观看、断电恢复、字幕字体切换与延迟的人机验收仍独立。
- 有目录、已有季集按钮或提示 toast，不等于准确同版续播已经通过。

所有失败证据保留；旧作重复回归不计作新增作品覆盖。
