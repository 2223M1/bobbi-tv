# 通用 CE：安装、进入影院与回退

产品目标是普通 CoreELEC/Kodi Python 3 影院，以现用 AM6B+ 为开发回归基底。
安装和基础业务不读取机型名单、是否测过或 Kodi 文件哈希；不要求 F9 私有接口，
也没有“未知设备继续安装”提示。包签名、组件身份、真实依赖和文件身份校验仍保留。
其他硬件的解码、HDR、直通与遥控体验由小范围内测补充，不把代码测试当成真机认证。

## 新用户只安装一个入口

1. 私下取得 `script.bobbi.start-0.2.3-ce2011.zip`（不是源码 ZIP，也不是改名的更新包）。
2. Kodi → 插件 → 从 ZIP 文件安装 → 选择该文件。Kodi 如询问未知来源或依赖许可，
   按其原生提示操作。官方 ABI 相关的 pycryptodome 由 Kodi 自动解析，需能访问仓库。
3. 打开“波比 TV · 开始使用”，确认安装完整影院。入口内已带同代签名的 22 组件。
   缺失的九个纯 Python 原版依赖从签名载荷补装；已有原版不覆盖、不降级、不改 origin。
   已有但过旧的依赖通过 Kodi/作者仓库更新，失败会提示具体依赖，不切换影院皮肤。
4. 在影院设置扫码登录自己的 115，或添加自己的 NAS。然后选择“进入波比影院”。
   TMDb 使用波比专用应用配置；不要求安装者自行申请 Key。
5. 点击作品后手动选源。基础分享播放和目录不需要 CD2、Jackett、ffprobe、BT 后台或 SSH。
   BT 是可选功能，可在设置中安装匹配 Kodi 用户态 ABI 的本机后台；不改系统服务。

字幕、字体和音轨沿用 Kodi 的设置，不重载皮肤或重启影片来切字体。已有中文旁挂在
ListItem 交付前绑定；后台匹配仍有 30 秒预算。普通 Kodi 没有原子字幕意图接口，
若匹配在开播之后才完成，会在“找中文字幕”提供本片候选供手动加载，不覆盖手动关闭。
原生增强路径保留既有字幕/字体准备链。ASS 内嵌字体与 Kodi 字体设置仍由播放器处理。

## 更新、退出与恢复

- 从 CE2009 入口更新时，先在 Kodi 安装新的 `0.2.3-ce2011` 入口 ZIP，再打开入口。
  旧入口内附旧 bootstrap，仅更新 platform 不能修复旧入口的安装恢复逻辑。
- 影院设置 → 更新与恢复 → 波比定制组件，进入同一个安装器。它先完整验证签名包，
  再停用本产品驻留服务、换程序并核验版本。播放中拒绝更新，不擅自停影片。
- 安装器管理 12 个影院组件；入口脚本自身由 Kodi ZIP 安装管理。开始前保存本轮程序备份。
  入口不含个人账号、Juku 私钥、CD2 配置、SSH 或旧观看库。
- 打开“波比开始使用”→“回退上一次程序安装”，只恢复程序与先前启用/皮肤状态。
  账号、媒体、观看数据不回滚。失败/中断时再次打开入口，会先恢复未完成事务。
  文件切换中断则恢复原程序；已验证文件但启用未完成则继续启用，恢复 RPC 失败则补齐
  原启用/皮肤状态。读回确认之后才宣布完成。不会因重开入口重复搬动已恢复文件。
- 新补装的原版依赖和 Kodi 自己下载的依赖保留，像正常依赖安装一样不随影院回退删除。
  它们保持原 ID/许可证；可在 Kodi 原仓库管理中更新，不能用原版覆盖波比定制组件。
- “返回原 Kodi 界面”恢复安装前皮肤（不适用时回 Estuary）。卸载用 Kodi 我的插件，
  不使用清库脚本；是否删除自己的 addon_data 由用户在 Kodi 提示中选择。

安装文件需本地存储空间容纳解包、上一版和恢复文件。空间不足或真实依赖下载失败会停止，
不会刷固件、SYSTEM/eMMC，不改 CD2、挂载、Yatse、系统 DNS、代理或音画设置。

保留其历史宿主校验；它们不是新用户安装入口，朋友不需要 transport-source、SSH 或 8080。
