## BT 根因与实机验证

原失败 hash：`b7b0126dc36050ad83725e9c9896365146be95ff`。引擎 journal 在 12:21:39 记录该 hash `Torrent close by timeout`，原应用于 12:21:41 手动核对后报 HTTP 拒绝。更早一轮 12:18:44 也有相同超时关闭记录。上游 MatriX.144.1 固定提交 `c6e1a1ee7408b315b74712266028a0be15777593` 的 GetTorrent 会延长空闲期限，缺失时 API 返回 404；未将缺失的原 HTTP 数字补造为实测记录。

CE2047 第 6 次回归中，通过普通选源找到同 hash、同一 `Meidoinabisu 2017 S01E01` 文件。自动化在已经观察到的选择框内额外停留 35 秒，再核对窗口/文件并确认；完整 selector 阶段约 60 秒，之后进入 `Torrent preload`，文件目录 13 项仍在。此结果关闭的是“人还在选文件时种子过期”的路径，不是 BT 影片播放验收。

此前第 5 次安排等待过晚，选择框的原 60 秒自动关闭已先发生，确认操作被 UI_CHANGED 拒绝；保留这次失败，不把它算作成功或用户主动取消。未延长选择框超时。

实测 BT 供数仍弱：第 4 次约 118 KB/s、预载 5.8 MB；第 6 次约 240 KB/s、预载 1.8 MB，而既有首段目标约 32 MB。均未 AV_STARTED，最后精确撤销当前测试请求；没有通过缩小缓存标准来制造通过。
