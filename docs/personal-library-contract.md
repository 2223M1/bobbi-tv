# 个人片库实现边界

本轮已构建集成候选，并在一台 CoreELEC 设备进行有限验收；不代表所有账号、格式或平台均已验证。具体源码身份、回执和未覆盖项见 [本轮验收记录](review-d030e04-validation.md)。选源界面、唯一播放 owner、115 PreparationQueue、账号凭据库和来源 Registry 继续复用。原生网盘与 CD2 挂载共享 MediaIndex、CatalogService 的唯一扫描循环、worker 和任务管理。

## 索引与扫描

目录登记使用原 `libraries.sqlite3` 的可选表；独立 `media-index.sqlite3` 保存 FileRef、来源成员关系、人工元数据、扫描 checkpoint 和修订。FileRef 只由 provider、稳定账号、namespace、file_id 定义，不能授权播放。标题、目录、账号 epoch、临时直链和作品映射不参与稳定文件键。

仅扫描用户明确选择的目录。默认预算如下，集中定义于 `catalog_service.py`。

| 项目 | 上限 |
| --- | --- |
| 执行并发 | 1 |
| 目录深度 / 已发现目录 | 12 / 1024 |
| 扫描项 / 页 / 网络尝试 | 12000 / 1200 / 2400 |
| 单页 / 总运行时间 | 20 项 / 1800 秒 |
| 任务历史 / 原始整理页面 | 128 / 最多 5 项并受 UTF-8 字节限制 |
| 作品查询页面 / 回复 | 默认 20、最多 32 项 / 最多 15000 UTF-8 字节 |
| 纠错批量 / 修订历史 | 5 项 / 每文件保留最近 32 次 |

当前网盘 adapter 的明确上限是每页 20 项，交互浏览仍为 10 项。扫描逐页让出网盘客户端锁，播放期间增加页间等待。只读操作共用截止时间、可取消退避与请求预算，不自动重试不明结果的远端写入。

`NativePort` 保留账号 CAS、网盘分页与重复页/游标证明，`MountedPort` 保留当前挂载、目录迭代与 stat 证明。两类来源进入同一个队列、深度/数量预算、checkpoint 和终态处理；端口不创建 worker 或另一份索引。旧 `catalog_mount_scan` 只适配到 CatalogService，原 MountedCatalog 的独立启动与 BFS 已删除。CD2 同样使用播放期间的页间让出策略；本地测试不证明具体设备上的首帧或输入延迟。

批次对象、成员关系、计数及 checkpoint 在同一事务提交；重复批次不重复计数。完整 generation 闭合才标记该来源缺席成员不可用。网络失败、限额、循环游标、取消和账号撤销都不能推断删除。移除本地来源不删除文件、历史或人工映射。

服务重启保留最后已提交结果，将未完任务标记 `interrupted`，用户重新扫描时开启新 generation。尚无可证明安全重放的 provider 游标合同，因此不宣称断点自动续扫或 exactly-once。取消请求先显示正在取消，worker 确认停止才进入终态；退出时无法排空则保留 Host 实例锁。

CD2 任务查看和取消绑定已登记来源、保存的任务及原根目录 namespace。掉线和同根目录重挂后仍可操作任务；改根目录、移除来源或传入别的来源任务会被拒绝。扫描中的挂载检查在共享任务锁外执行，锁内只处理本地取消状态与事务。阻塞中的系统调用返回后，worker 才确认取消；界面先显示取消请求已记录。涉及多个本地锁的发布边界遵循 PanService → CatalogService → PanAccounts → MediaIndex 的顺序；扫描提交先取得 CatalogService 锁再执行账号 CAS，点播发布在已有 PanService 锁内取得 CatalogService 锁。远端目录读取与完整 FUSE 校验仍在此边界之外。

## 作品查询与观看

`CatalogQuery` 是 MediaIndex 同一数据库中的可重建 SQL 投影，提供作品、季、集、原文件四级查询。查询不解包全库 FileRef。游标绑定查询条件、账号代际或本地来源范围、投影 generation、scope revision 及最后排序键，保留最多 128 个、有效期 10 分钟。scope revision 与对应对象、成员关系或映射变更在同一写事务内更新；其他账号写入不打断当前分页。同范围变更、投影重建、重启、挂载观察变化或超时会明确返回 `CATALOG_CURSOR_STALE`，界面保留筛选条件重新查询，不承诺跨并发写入的 MVCC 快照。

CD2 描述范围固定为已登记的 `source_id + namespace`，不再按当前 mount generation 隐藏旧卡。掉线时标记 `source_unavailable`；同根重挂或设备重启使挂载观察变化后，旧观察标记 `unverified`，待当前文件复核。仅重启 Host/Kodi 而 kernel boot/mount 观察不变，不会凭空制造新的挂载代际；播放仍需 fresh-list/stat。原始描述、人工整理和观察历史保留，任务历史淘汰也不隐藏仍有作品的来源。改根目录不会继承旧 namespace，删除来源也不会让旧授权扩展到其他来源。

电视的原生网盘与 CD2 入口共用 `personal_catalog` 的作品/季/集/文件 renderer、检索、分页与整理路由。作品到季、集和文件的下钻保留来源与筛选条件；季和集发布 Kodi 原生 content 类型以启用现有皮肤布局。片库根页仅保留一个“我的作品片库”入口，CD2 在该入口内选择来源。旧 mounted URL 保留短重定向，原目录浏览仍可用。确认后的公开 metadata key 经已有 metadata 缓存/队列补充展示；年份和海报等描述不携带私有 URL、selected 或播放票据，也不证明两个文件属于同发行版。同一次个人片库分集渲染按作品/季复用现有 EpisodeProjection，避免逐卡重复读取同一公开缓存；下一次渲染重新读取，不增加常驻缓存。

网盘卡片经现有有界目录枚举再次匹配原文件，然后领取一次性播放票据。CD2 使用独立的 mounted_path 类型、来源及挂载证明，经目录枚举与 stat 复核进入既有播放入口；该类型当前明确返回 `resume_supported=False`。人工映射、作品聚合与海报元数据均为描述信息，播放权限继续由实际来源核验。

重挂或同名替换后，普通 `play` 不接受旧观察。用户明确选择“选择当前文件并从头播放”才发送 `play_from_start`，在当前目录重新枚举并 stat，记录新观察并保留最近 32 份旧证据，再发放绑定当前请求的一次性票据。原稳定 MountedRef 键不变，但不从旧观察、旧票据或作品映射迁移精确进度。票据领取及最终交接继续校验当前来源、观察和播放意图。显式重选成功观察到先前缺失的文件时，在同一事务内恢复该 source/file 的正向可见状态并推进 scope revision；保留扫描 generation、其他文件的缺失状态和旧观察，不把单文件复核当作整树扫描完成。对于复核时已在途且 source/namespace/mount generation 一致的扫描，同一 SQLite 连接的临时 task/file 表保护该点观察，避免旧批次覆盖 ref 或旧终态再标缺失；扫描真实枚举的计数照常记录。保护与点更新同事务，终态、恢复及下一次空闲启动时清理，不持久化，也不妨碍后续独立完整扫描再次确认缺失。

## 人工元数据与历史

文件名只产生保守建议。自定义名称仍标记未匹配；TMDb 类型、编号和季集均为人工描述，不自动获得同发行版、下一集或可播放证明。单项和批量操作先预览，带 expected_revision 提交，返回每项真实结果；安全重试复用请求 ID。撤回仅在修订匹配时恢复前值，不覆盖后续编辑。

FileRef 与 MountedRef 通过同一 typed lookup 进入既有 reviews、review_changes、receipts 和 CAS，不另建 mounted_reviews。电视与手机均可对具体原文件执行候选确认、解绑、忽略和撤回；只读单条入口不需要遍历整页索引。CD2 整理验证本地登记范围，不要求 FUSE stat 成功；它不会打开文件或生成播放票据。

电视与手机已接入 TMDb 候选搜索及季集批量建议。保存一集后可明确选择“继续整理本剧”，只按可信来源和父目录产生逐项建议，不自动绑定其他文件。手机一次整理最多 100 项，按最多 5 项分批；每个尚未提交的子批次在写入前重新预览原 commands 和 expected_revision，继续使用原请求 ID。此时发生修订冲突会停止后续提交并保留已完成回执。写入结果未知时使用既有回执查询及同 ID 恢复流程。

手机默认先按作品查询，保留筛选、页码、层级返回和选中项；点开具体文件才读单条整理记录。一次整理不能覆盖仍待确认的未知提交。跨 100 项目录需要用户明确进入下一轮；每轮重新读取当前修订、逐项预览，不自动把后续文件加入已有提交。通用 Python 分批计划位于 core 的 catalog_review，TV 调用不再依赖 TMDb 客户端来执行批次编排。

早期桌面合成片库确认 100+5 轮共 105 个不同文件写入；该轮另一个丢响应 fixture 的恢复/取消不足保留原记录。新隔离 IAB 批次通过“核对原提交”找回同 ID 的已保存结果，未新增 apply，四张整理表前后不变；100 项计划点击停止后保留已保存 45 项（含在途最后 5 项）、55 项未启动，后续 64.847 秒无新 preview/apply。新旧批次不混算；实际手机、真实账号和其他故障路径仍未据此验收。新会话已撤销、IAB 测试页和临时服务已清理；从未访问 fixture 的 Chrome about:blank 页关闭 API 失败，不宣称它已关闭。详细回执及工具限制见本轮验收记录。

个人文件历史复用原有异步写入边界；保存稳定引用和本地进度，不保存播放地址。续播重新检查当前账号和原文件，再领取一次性播放票据。领取票据时仅预留新的历史生成号与 session；已有进度及其原 FileRef 保持成对，当前 FileRef 随新会话的第一次真实进度报告一起写入。打开失败或取消不会把旧进度重新标为替换文件的记录。历史生成号继续阻止迟到的旧播放进度覆盖新会话。

## 手机与回退

手机管理扩展已有按需 Web 服务，不重复保存片库。电视明确确认后开启最多 15 分钟会话：原生网盘仍绑定原账号与 epoch；CD2 单独绑定固定 source_id 和 namespace，不依赖本次挂载 generation。每次请求重新校验登记范围，并把固定 namespace 传给后端；同根重挂不扩大权限，改根、移除来源或账号切换会撤销旧会话。CD2 会话不提供原生文件历史、播放或凭据读取接口。

一次性 fragment 配对、严格 Host/Origin、HttpOnly cookie、CSRF 和固定 RPC 白名单共同限制访问。仅可信局域网使用，HTTP 不提供传输加密。关闭二维码立即撤销管理授权，不取消后台扫描。原 Stremio 和字幕入口保留，管理模式不开放旧的匿名修改路由。

不打开详细管理即可继续原文件浏览。新增 scope revision 和 typed observation 表是辅助元数据；原 objects、typed_objects、reviews 与历史不逆向删除，FileRef v1 与 MountedRef 稳定键语义不变。当前索引 user_version 保持 2，读取投影 schema 为 5；升级在事务内重建投影，失败可回滚并重试。支持 schema 2 的旧版本可重建自己的读取投影，辅助表和用户记录保留；不支持的索引 schema 继续拒绝写入。没有设备和真实账号证据的网盘能力继续标记 `not_device_verified`。

## 首页与播放摘要

公共 runtime 管理 HomeRailLifecycle，native 与 standard 主循环均发布当前账号范围，并消费一个 WidgetRefreshService 后台采样器的容量一邮箱。历史读取与 SQL 查询留在后台；owner tick 只发布有界行修订。账号撤销立即清除旧范围，关闭时先撤销展示，再排空采样器，最后释放 Host。保留 Kodi 自身目录刷新时按稳定路径恢复当前项的行为。

下一集摘要复用已有续播状态，只提供显示。旧格式或非结构化元数据使摘要保持 unavailable；展示投影异常会清理旧标签，实际播放观察与终态处理继续执行。

## 原生片尾证据

既有 TERMINAL receipt 可携带同实例 `completion_observation`，严格限定 `schema=1`、`position_ms`、`duration_ms`、`age_us` 和 `valid`。位置与时长来自相同媒体时基，年龄由 native 内部单调时钟计算；Python 不跨时钟原点相减，也不在终态后查询新播放器来证明旧实例。receipt 仍须通过原有 request/instance/账号与取消边界，位置字段不能创建 EOF 或控制权限。

历史完成与一次性下一集共同消费 `playback_completion.terminal_end`。只有匹配的 `NATURAL_EOF`、有效已知时长、距尾不超过 3000 ms 且年龄不超过 5000000 μs 才可完成。新字段存在但 unavailable、过期或不完整时失败关闭；只有旧 native 完全缺少该字段才使用唯一保守轮询兼容分支（近尾 3 秒、观察年龄最多 5 秒）。不能把新旧证据 OR 在一起放宽完成条件。

当前新证据针对普通、静态、已知时长视频。ISO/display-time、live/menu、ITimes、EDL、非零 PTS offset 和未知时长返回 unavailable，不宣称已支持这些时基的终态完成。canonical patch apply、受影响 C++ 编译、CE 完整链接、封装、部署和真实 EOF/历史/next 闭环分别记录；编译或 native EOF 单项通过不等于整条闭环验收完成。

2115 的单台设备 8×、32×切片分别确认同实例有效 EOF 和 exact history 完成，进度为 100%，修复了此前过冲；next 日志仅区间归属，1×最终历史也未收齐。样本不是同一文件速率配对，旧 2114 暂停/Stop 负控不重新标为 2115 全矩阵通过。

2116 后续独立切片补到 1× 同实例有效 EOF 与 exact history=100%，以及新实例 Stop 后保持未完成。不同集数与代际不合并成速率配对；next 精确 handoff 归属仍未补齐。首页原生列表在 Fetch 同锁发布边界求值可见性，12 项生产方法/两组负控及一次 40 秒真实刷新观察通过，未新增焦点轮询或放宽账户可见性。

## 测量边界

`BLOCK_DELIVERY_SECONDS=1.0` 是收到可用前缀后的交付检查窗口，不是连接、DNS、首字节、系统调用或整次请求的硬超时。现有 `raw.read1` 与精确 suffix 续取继续保留；本轮不因短样本推断而新增缓存、transport 或调度器。

已采单台设备首页暖态及普通视频短窗口的 CPU、进程 RSS 和既有稀疏 trace，并绑定各自实际 tree、组件与 native 哈希。2114 第二轮采样已覆盖真实扫描 running 15.107 秒。2115 另采同一 ISO 播放实例的无扫描 55.002 秒及扫描 running 15.092 秒顺序片段，三个离散时钟窗各 5 点均为 1×、caching=false；它们不连续覆盖 CPU 窗口，不是随机重复配对，也不证明整片无卡顿。2114/2115 视频样本分开统计，不据此声称代际优化。冷/暖配对、精确首帧/seek/输入延迟及精确 Range/上游流量仍待验收；一次 first-AV 抓取失败不因后来播放成功而改记通过。CPU 以单核 100% 为进程口径；RSS 不等于 Python tracemalloc，短时增长也不能单独证明泄漏。无足够样本时不作“最快”或性能优化完成的结论。

## 本地验证

新增测试覆盖事务故障、重复页、重叠来源、跨账号、取消与迟到回包、重启、修订冲突、撤回、Unicode 消息边界及手机会话。合成一万文件、多层目录采用 511 页；实际测量另存执行回执。Python tracemalloc 峰值不等于进程总 RSS，模拟吞吐不等于真实网盘性能。

四组 pytest 分进程运行，其中包含 IPC/安装残留等边界用例，另执行两次 source-check 构建比较。没有独立回执的探针不另计一次验收。真实账号、TV/Android 设备、生产签名与正式发布单独验收，不以本地测试替代；本轮设备扫描、分页、取消及部分 UI/播放结果按 [验收记录](review-d030e04-validation.md) 的精确范围列出。

设备试播清单统一保存在 `tools/ce_trial_cases.json`，CLI、远端脚本注入和只读身份核验共用该声明，产品 runtime 不导入设备脚本。已删除无调用者且会覆盖现有远端实现的旧一次性导入器 `tools/import_playback_trial.py`；其 SHA256 为 `a093b2e5aef4d11249e915073626dc8cfc34fbc5d6075dfc3438ab1790ad0dfe`，原审阅来源 `release317/trial.py` 的 SHA256 为 `d92d7c33c74027b6c6ca0ceb2b4c4e5625d621c3f670f8fd00b7b0d15aa6a87f`。两者仅为来源记录，不重新生成或覆盖当前工具。
