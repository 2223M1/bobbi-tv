# 同一部片为什么在另一款皮肤能播？以后怎样验

**先对齐输入。** 记录作品、季集、发行版本、传输方式、文件 ID、路径和字节数。对「BT 哈希 | 文件 ID | 文件路径 | 字节数」取 SHA-256；记录这个指纹即可，不记录播放地址、账号或签名。相同海报、相同文件名、另一份 115 副本都不能单独证明测的是同一文件。

开始前照[观影回归总表的 CEC 检查](operations/am6b-viewing-regression.md)确认家庭与隔离配置不会开关电视或强制切源；未通过不要切皮肤或重启。

1. **先走家庭用户的完整路径。** 从作品详情点到源卡，遥控器选定指定版本。确认已有引擎列表里没有该种子，再从公网读取。保留按键、用时、是否出现文件弹窗及是否手动继续。测试只有一个符合当前集的文件时，任何额外文件选择框都算失败。
2. **再单独对比皮肤。** 同盒、同 Kodi、同引擎、同一个已核对的流。两个皮肤都从 Kodi 原生视频目录，遥控器点开相同内容的 .strm。记录实际加载的皮肤清单、缓存分块大小和读数。不拿暖缓存与冷起播比速度。对照使用隔离的 Kodi 配置，结束后恢复原皮肤并核对家庭插件、账号和首页。
3. **从真正的播放器验收。** 用进程内 Player.getPlayingFile() 核对所读文件的指纹；Kodi 对外的 JSON-RPC 可能会隐去 URL 查询参数。再核对全屏、视频分辨率、正常速度和多次播放时钟。预载 100%、HTTP 200、识别出 1080p、走时只有零点几秒都不算通过。连续性单独计分：采样间隔异常、向前跳跃或长时间停住会切断该段；不能把前后两段相加。本轮冷起播连续目标 50 秒，同输入皮肤对照目标 20 秒。
4. **根据差异修在正确的地方。** 两款皮肤拿到的文件不同，先查筛选、来源、账号和解析。只有波比从源卡失败而两款原生目录都成功，查波比交接、焦点和取消。两款拿到同一流都停在相同的读位置，查本地供数、容器索引和 Kodi 实际 Range。某个系统先云盘离线下载，应作为另一条传输路径单列；不能算作公网 BT 成功。
5. **保留失败。** 除起播外，保留冷启动耗时、重缓冲以及成功持续多久。测试结束要验证主动停止没有打开下一集、不同账号未被替换、非 BT 来源和液态玻璃正常。

把本次「证据」目录交给`check_bt_playback_parity.py` 可离线重新判分。例如 `python check_bt_playback_parity.py 证据/对照清单.json`。缺任一对照、文件身份不同或未达到连续时长都会以非零退出。这个检查衡量测试到的输入，不能替未测试的源作保证。

验收工具在 [tools/check_bt_playback_parity.py](../tools/check_bt_playback_parity.py)。清单的每个 cases 条目指定 name、product、cold_before、file_dialogs 和 views；每个 view 指定实际 skin 和该轮 receipt 的 JSON 文件名。换源、改网盘或变更同片版本需要另列用例。

从[观影回归总表](operations/am6b-viewing-regression.md)进入本流程。记录每个原生目录样本的窗口号（视频全屏为 12005）、播放速度、解码尺寸和文件匹配结果。验收器要求有波比家庭皮肤和一个不同的参考皮肤；逐片列出「参考能播而家庭目录或产品冷起播不能」的差异。个别回执缺失也会保留其余片的结果，并以非零退出。
