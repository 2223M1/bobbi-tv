# R19 液态玻璃 · CoreELEC

R19 设计输入是 2026-11-22 最后的 GLES2 源码（SHA-256 前缀 `7a4076f2d099`）和配套的 16×4 材质标签，不是 R18 的插件版本号。私有组合 2156 保留 R18 已修的焦点、指针、HUD、播放及自然片尾。玻璃只装饰已有窗口；不创建第二套首页、选源或播放器。

R19 的区域采样、缓存和折射用于导航、面板及部分无图卡，不接管普通海报或硬件视频平面。预渲染或无渲染器时使用 Kodi 自身贴图；控制中心全屏采样层回退为透明。首页不再同时要求 TMDbHelper 在选片或切焦时生成另一份模糊图片。减少动效与静态玻璃是两个独立设置。

CE 附加渲染器从 `ui/liquid_glass/build.sh` 交叉构建；`ce_service.py` 在每次 Kodi 启动时核对签名安装状态中的精确组合、磁盘四个插件版本、本机 Kodi 可执行文件和模块摘要，缺一则不启用。systemd 只对 Kodi 服务生效，不修改固件或播放内核；帧统计写入私有易失目录。禁用专用 drop-in、daemon-reload 后重启即撤销渲染器，用户库与账号不动。组件回退仍走既有产品数据兼容检查。Android 不装此 CE ARMHF 渲染器。

### 原厂 CoreELEC 21.3：区分 ZIP 外观与实时折射

AM6B+ 上从原厂 Kodi 的 ZIP 浏览器将 CE2179 装到空白用户目录，切换并保留 Bobbi 皮肤后，默认有玻璃材质，但进程没有加载实时渲染器。该 ZIP 本身不安装系统启动项。

同一份已安装的插件，在隔离的临时 Kodi 服务中重启 **原厂** 可执行文件（SHA-256 `793194b0e506a61ab2f1a065fb7dd0395c80d281fe853e48f1150adbc2879b2e`）后，带校验的启动器可加载包内 ARMHF 渲染器。首页实时／经典／恢复实时三次采样的绘制区域为 **3／0／3**，累计模糊运算 **24／24／28**；控制中心采样区域覆盖 1920×1080。片段从 0 秒播放至 2 秒，暂停不走时，恢复至 4 秒后停止。这证明的是该原厂内核与渲染器兼容，不代表普通 ZIP 已经能自行启用它，也不是其他 CE 机型、架构或版本的验证。测试没有安装持久系统服务。

## 2026-11-22 实机验收

AM6B 当前运行 CoreELEC 私有组合 **2026102156**：皮肤 **0.1.25**、视频插件 **0.1.82**、core **0.1.83**、platform **0.1.84**。签名包对应源码 `64fefc57`，安装没有数据迁移。相对 2155 仅皮肤和视频插件两个组件的归档发生变化；设备上 700 个皮肤文件与包一致。22 个组件中安装器处理过的第三方文件仍有前版相同的 58 处差异。

**画面。** 在盒上读取实际显示的 framebuffer 页；十张 PNG 均为 1920×1080、无后期，传回后逐张核对设备 SHA、PNG 校验和和解压长度。首页、左栏、控制中心、设置都有原图。在同一作品、同一窗口、同一按钮焦点下通过皮肤设置切换材质：实时 / 预渲染 / 恢复实时的末帧分别画了 **13 / 0 / 13** 个玻璃区域；观察窗内模糊计算增加 **140 / 0 / 150** 次，三段都有新交换帧。预渲染不是旧帧冻结。终态为实时。带本机片单的截图只交付到维护者本地，未放进产品仓库。

**操作。** 从首页和个人页用 Kodi 方向键操作「我的」↓「设置」↑「我的」，确认进入设置再返回，焦点落回原入口。20 张卡的第 17–20 张，指示条的实际像素位置依次为 **1013、1023、1033、1043**；来回六步都有中间帧。减少动效时只改变位置，原设置已恢复。音量 HUD 确认音量变化、超时消失并还原；控制中心按下再按上可回到原焦点。H.264 / 解码 AAC 测试片经电视原生速度菜单，硬件视频时钟相对墙钟为 **1.002 / 1.196 / 0.903 / 1.000**，ALSA 未静音、指针前进；暂停时左右不误调。测的是电视接收的 Kodi 遥控输入，不是实体 Yatse 手机、扬声器录音或音频直通倍速。

**续播。** 独立短片触发一次有原实例标识的 `NATURAL_EOF`。下一集 S1E2 缺同源但有一个其他来源，原选源窗 13001 打开且可操作，播放实例为零；在来源与筛选间上下往返，无测试片历史残留。没有为此改选源布局。

**原盘。** 同一份 49,731,141,632 字节的 115 分享 ISO、同起点、音轨 0、字幕轨 1 开启。5 次重启 Kodi 后首次播放，配对 5 次同进程、新票据重新开片。十次均越过原 23.57 秒卡点：每次 30 次采样，窗长 32.01–33.05 秒，290 个硬件视频时钟区间都推进，零平时钟、零缓存等待。十次停止均确认原命令生效并回原进程首页；第四组冷开的第一次停止响应不确定，只查询了原命令，没有重发。这里没有冲洗 CDN 或操作系统缓存，也不能从十次样本推算 P95。早暂停 30 分钟是[上一组合的独立观察](r18-device-acceptance.md)，不混入这十次；有界预读不是缓存半小时内容。现有 CD2 挂载没有同一文件，未做伪对照。

**普通分享 MKV。** 与原盘分开，用同一个 6,137,957,865 字节的文件、相同音轨和字幕、同一内核，依次比较既有的两种受权读取方式。各取 60 个约一秒间隔的采样点。账号未变；切模式走现有维护工具，重启 Kodi 后重新选片，不改 Kodi 缓存或画质。

第一轮从片内 8.1 秒附近开始缓存时，传输仍在交付字节；不能把现象归结为断网，更不能从稀疏的单块事件推算全程网速。三次边读边交付都没有平时钟，只在本台 AM6B 上保留既有的 `progressive` 偏好，不改其他设备的默认。恢复方式是在空闲时通过同一 `tools/ce_transport_mode.py` 设回 `block`；回执保存在本机。最终配置再独立开同一 ISO，片内 3.788→68.812 秒，墙钟 65.144 秒，59/59 个硬件区间前进，零平时钟、零缓存等待，收到原停止回执。不能据此宣称所有 115 片源或整部影片都不卡。

**收场。** 无新增 Kodi 崩溃文件或服务崩溃记录，剩余空间 1,501,782,016 字节。渲染器已加载，实时玻璃开启、减少动效还原，最后停在有作品图的「继续观看」，无活动播放器。真实 ISO 开片使测试影片的本地观看记录更新到约 0.3%；没有用推测值覆盖旧进度，后续对照只用不写观看历史的测试输入。原始回执和截图不随仓库发布。

**离线。** 对正在运行的产品源码，Python 联合回归（含四个 Android 门禁）为 **11,434 通过、32 跳过、1 个既有预期失败**。预期失败是动画搜索结果中一条缺少类型证据的真人剧，不是玻璃或播放错误。五组 JS 前端测试共 64 通过；首页生成文件校验通过，两次 source-check 构建的 22 个组件及全部 63 个输出文件逐字节相同。这不是 Android 真机验收。

另外修复了独立字幕验收工具遗漏页对齐读取函数的问题，并使全帧截图与局部截图一样拒绝不支持的横向偏移。旧实现的独立捕获可复现 `NameError`；修正后相关 80 个测试通过，独立捕获函数也在真机首页读取并校验了 1920×1080 的 PNG。这是维护工具改动，不改变上表签名包或原生二进制。

**公共片单。** 本地继续观看和个人片库可以加载；四个公共推荐栏走了可重试的失败状态。盒上图片域名 TLS 可用，公共元数据 API 走既有透明中继时握手提前结束，中继日志有连接超时。未发现足以判定 API 密钥失效的证据；没有改外部中继、主机映射或 TLS 校验。
## CE2181：普通 ZIP 的玻璃开关

首次安装使用经典外观。设置中手动开启时说明本机将得到的效果：已验收的 AM6B+ 原厂 CE 21.3 Kodi 在主配置下可安装专用启动项，用户自行重启后生效；已经加载适配渲染器的机器直接开启；其他宿主只使用皮肤内的玻璃材质。取消不写入，关闭移除 Bobbi 自己的启动项。不会替换 Kodi、重启电视盒或覆盖管理员的启动器。
